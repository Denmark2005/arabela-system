{% comment %} The cancel window for Active Reservations. One window, three jobs, picked by the button that opens it (data-mode): * booking (default) -- "Cancel booking": the whole booking (arabela_admin.views.reservation_cancel_view). Nothing happens until the booking code is typed exactly, so it can't happen by accident. * gown -- "Cancel gown" on one gown's row (arabela_admin.views.reservation_cancel_gowns_view). A small confirm, no typing: it is one gown, the rest of the booking is untouched, and "Keep gown" is the first thing the eye lands on. * gowns -- "Cancel all not picked up": every gown of a booking that nobody collected, in one go (same endpoint). The same window also sends a CANCELLATION REQUEST (data-request="1") for a staff account that may not cancel: no booking code to type, the button says "Send request", and the booking stays as it is until the owner answers (reservations/cancel_requests.py). The owner's Approve / Decline and a staff member's Withdraw, on a booking that has a waiting request, are the .cr-act buttons below. One small, self-contained piece: its own styles (the admin's compiled CSS only has the classes the pack itself uses), its own markup and its own script. Every button with class cb-open-btn opens it and hands it the details through data- attributes. {% endcomment %}
